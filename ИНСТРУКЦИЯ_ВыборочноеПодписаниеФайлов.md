# Инструкция: расширение «ВыборочноеПодписаниеФайлов»

Расширение конфигурации для **1С:Документооборот КОРП 3.0** (ред. 3.0.20.21) — выборочное подписание электронной подписью (ЭП) отдельных присоединённых файлов документа в процессе «Подписание».

---

## 1. Назначение

Документ содержит несколько присоединённых файлов. Подписант непосредственно перед подписанием выбирает, какие файлы подписать ЭП:

| Подписать | Файл            | Тип | Размер | Подписан ранее |
|-----------|-----------------|-----|--------|----------------|
| ☑         | Договор.pdf     | PDF | ...    | Нет            |
| ☐         | Приложение1.pdf | PDF | ...    | Нет            |
| ☑         | Приложение2.pdf | PDF | ...    | Нет            |

После нажатия «Подписать выбранные» ЭП формируется **только** для отмеченных файлов. Остальные файлы остаются в документе без новой ЭП. Исходные файлы не изменяются, подписи хранятся штатным способом ДО.

## 2. Ключевой принцип

**Собственная криптография не используется.** Расширение только определяет, **ЧТО** подписывать (выбирает/фильтрует список файлов), а 1С:Документооборот **штатным механизмом** определяет, **КАК** подписывать. Не вычисляются хэши, не создаются контейнеры подписи, не реализуется CAdES/CMS, PDF не изменяется.

## 3. Состав расширения

| Объект | Тип | Роль |
|--------|-----|------|
| `ИнтеграцияЗадачКлиент` | Общий модуль (заимствованный, `ObjectBelonging=Adopted`) | Перехват `&Вместо("ОбработатьДанныеВыполнения")` |
| `Расш_ВыборФайловДляПодписания` | Общая форма | Интерфейс выбора файлов для подписания |

Реквизит формы `Файлы` (ТаблицаЗначений) с колонками: `Выбрано`, `Файл`, `Наименование`, `Расширение`, `Размер`, `ПодписанЭП`.
Команды: «Выбрать все», «Снять все», «Открыть файл», «Проверить подписи», «Подписать выбранные», «Отмена».

## 4. Принцип работы (точка интеграции)

```
Задача «Подписать» (результат «Подписано»)
   ↓
РаботаСЗадачамиКлиент.ВыполнитьДействиеЗадачи
   ↓
ИнтеграцияЗадачКлиент.ОбработатьДанныеВыполнения  ← точка перехвата (&Вместо)
   ↓  [если предметов-файлов > 1 и это подписание ЭП]
Форма «Расш_ВыборФайловДляПодписания» (выбор пользователем)
   ↓  [фильтрация НаборыПредметовДляПодписания]
ИнтеграцияЗадачКлиент.ОбработатьДанныеВыполненияПодписатьПредметыЭП
   ↓
РаботаСЭПКлиент.Подписать(Массив выбранных файлов)
   ↓
Штатный механизм ЭП (БСП «ЭлектроннаяПодпись», «СервисКриптографии»)
   ↓
Запись подписей в регистр «ЭлектронныеПодписи»
```

Набор подписываемых объектов лежит в `КонтекстВыполненияЗадачи.ДанныеВыполнения.ДополнительныеПараметры.НаборыПредметовДляПодписания` (Соответствие: ключ — действие задачи, значение — массив предметов). Расширение отфильтровывает это соответствие, оставляя только выбранные файлы (`СправочникСсылка.Файлы`); предметы-не-файлы сохраняются без изменений.

Маркер `Расш_ВыборочноеПодписание_ВыборВыполнен` защищает от повторного показа формы при повторном входе в диспетчер (повторный вызов `ОбработатьДанныеВыполнения` после подписания).

## 5. Поведение в краевых случаях

- **Ничего не выбрано / «Отмена»** — ЭП не формируются, задача не завершается, пользователю показывается предупреждение.
- **Один файл** — форма выбора не показывается (сохраняется близкий к штатному UX).
- **Отмена сертификата / PIN** — штатный `Результат.Успех = Ложь`; возврат к задаче без повреждений и ложного успеха.
- **Частичная ошибка** — итог формируется по факту; текст штатной ошибки не скрывается.
- **Повторное подписание** — существующие подписи не удаляются; добавляется новый порядковый номер в регистре «ЭлектронныеПодписи».
- **Версии файлов** — подписывается версия, которую штатно считает актуальной ДО; версия не подменяется.

## 6. Требования

- Платформа **8.5.1.1343** (`C:\Program Files\1cv8\8.5.1.1343\bin\1cv8.exe`).
- 1С:Документооборот КОРП **3.0.20.21** (CompatibilityMode `Version8_3_27`).
- Для реального подписания: КриптоПро CSP + действующий сертификат подписанта.

## 7. Сборка расширения (.cfe)

Сборка выполняется **только через Конфигуратор** (пакетный `/Extension /LoadConfigFromFiles` в платформе 8.5.1 НЕ создаёт расширение).

1. Откройте ИБ в **Конфигураторе**.
2. Меню **Конфигурация → Расширения конфигурации → Добавить → «Загрузить из файлов»**.
3. Укажите папку `src/ВыборочноеПодписаниеФайлов`.
4. **F7** (Обновить конфигурацию базы данных).
5. Правый клик по расширению → **«Сохранить расширение в файл»** → сохраните `.cfe` (например `build/output/ВыборочноеПодписаниеФайлов.cfe`).

### Особенности формата XML-выгрузки расширения (платформа 8.5.1.1343)
Отличается от классического 8.3 — важно при ручной правке `Configuration.xml`:
- корневой объект — `<Configuration>` (не `<Extension>`);
- обязателен блок `<InternalInfo>` с 7 элементами `<xr:ContainedObject>` (фиксированные `ClassId`);
- назначение — `<ConfigurationExtensionPurpose>` (значения: `Customization`, `Adaptation`, `Patching`, `AddIn`);
- свойства `MainConfigurationCompatibilityMode` **нет**;
- `ConfigurationExtensionCompatibilityMode` = `Version8_3_27`;
- заимствованный объект: `ObjectBelonging=Adopted` + **уникальный** uuid (не совпадающий с uuid объекта основной конфигурации); собственные объекты — без `ObjectBelonging`.

## 8. Установка в рабочую базу

1. Конфигуратор → **Конфигурация → Расширения конфигурации → Добавить → «Загрузить из файлов»** (или подключить `.cfe`).
2. F7 — обновить конфигурацию базы данных.
3. Убедиться, что расширение активно (галочка «Активно» в списке расширений).

## 9. Использование

1. Документ с несколькими файлами отправляется на подписание (штатный процесс «Подписание»).
2. Подписант открывает задачу и нажимает штатную команду результата «Подписано».
3. Появляется форма выбора файлов — отметить нужные файлы.
4. Команды «Выбрать все» / «Снять все» / «Открыть файл» / «Проверить подписи» для предпросмотра.
5. «Подписать выбранные» → штатный выбор сертификата и подписание выбранных файлов.

## 10. Проверка

- **BSL LS**: 0 Error/ParseError в обоих модулях расширения.
- **Сборка**: `.cfe` формируется и загружается в ИБ без ошибок.
- **Приёмка (§24–31 ТЗ)**: выборочное подписание (2 из 3, 1 из 3, ни одного, уже подписанный файл, отмена сертификата, повторное открытие карточки, регресс штатного подписания) — требует прогона на рабочей базе с КриптоПро; в среде разработки не выполнялось.

## 11. Безопасность

- Пароль 1С хранится в DPAPI-контейнере и читается на время запуска; скрипты: `%LOCALAPPDATA%\opencode\1c-secrets\Set-1CPassword.ps1` (создание) и `Get-1CPassword.ps1` (чтение). Пароль не хранится в репозитории и не пишется в логи.
- Расширение не обходит RLS и штатные права, не эскалирует доступ, не сохраняет закрытые ключи.

## 12. Ограничения

- Реальное подписание требует КриптоПро + сертификат + ввод PIN — в среде разработки не проверено (RUNTIME/ACCEPTANCE = NOT_RUN).
- Внутренний контракт флагов `ПодписатьПредметыЭП` / `НаборыПредметовДляПодписания` — при обновлении КОРП 3.0 требуется регресс-тест.
- Семантика завершения задачи после частичного подписания фиксируется бизнес-правилом заказчика (штатно результат «Подписано» завершает задачу независимо от числа подписанных файлов).
