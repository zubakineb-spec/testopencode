# VYBR_PODPISANIE-001 — Architecture Report (выборочное подписание файлов ЭП)

## ВАРИАНТ: C — фильтрация набора предметов ПЕРЕД штатным вызовом движка ЭП.
Обоснование: штатный РаботаСЭПКлиент.Подписать уже принимает СПИСОК объектов/файлов, поэтому цикл по одному файлу (B) не нужен,
а вариант A (подписание документа целиком) сужается до выбранного подмножества — фактически C. Минимально инвазивно, криптографию не трогаем.

## ТОЧКА ПЕРЕХВАТА
&Вместо на Функция ИнтеграцияЗадачКлиент.ОбработатьДанныеВыполнения(КонтекстВыполненияЗадачи, ФормаВладелец) Экспорт.
Признаки (в ДополнительныеПараметры): ПодписатьПредметыЭП=Истина; НаборыПредметовДляПодписания (Соответствие).
Если предметов-файлов > 1 и маркер «выбор выполнен» отсутствует -> показать форму выбора, вернуть Истина;
иначе -> ПродолжитьВызов. Фильтруются только СправочникСсылка.Файлы; предметы-не-файлы сохраняются.

## СОСТАВ РАСШИРЕНИЯ (2 объекта)
1. Общий модуль ИнтеграцияЗадачКлиент (ObjectBelonging=Adopted) — &Вместо("ОбработатьДанныеВыполнения") + вспомогательные функции.
2. Общая форма Расш_ВыборФайловДляПодписания (ObjectBelonging=New) — таблица файлов (Выбрано/Файл/Наименование/Расширение/Размер/ПодписанЭП),
   команды Выбрать все/Снять все/Открыть файл/Проверить подписи/Подписать выбранные/Отмена; заполнение на сервере (ПриСозданииНаСервере).

## КРАЕВЫЕ СЛУЧАИ
- Пустой выбор/Отмена -> без ЭП, задача не выполнена.
- Отмена сертификата/PIN -> штатный Результат.Успех=Ложь -> возврат к задаче.
- Частичная ошибка -> элементы без СвойстваПодписи пропускаются штатно; итог по факту.
- Повторное подписание -> новый ПорядковыйНомер в РегистрСведений.ЭлектронныеПодписи; старые подписи не удаляются.
- Версии -> подписывается текущая версия (штатно); версия не подменяется.
- Один файл -> форма не показывается (близкий к штатному UX).

## КЛИЕНТ/СЕРВЕР
Перехват и форма — клиент; заполнение списка — сервер (&НаСервере ПриСозданииНаСервере); криптовызов — штатный контекст ДО.

## СЕМАНТИКА ЗАВЕРШЕНИЯ ЗАДАЧИ
Штатно результат «Подписано» завершает задачу независимо от числа подписанных файлов. Для выборочного режима бизнес-правило
(допустимо ли «частичное» подписание) фиксируется заказчиком; при требовании полного подписания задачу завершать нельзя.

## РИСКИ
Внутренний контракт имён флагов/набора предметов — при обновлении КОРП 3.0 требуется регресс-тест.
