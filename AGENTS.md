# AGENTS.md — проект разработки 1С

Проект предназначен для разработки внешних обработок и конфигураций 1С:Предприятие.

## Платформа и инфобаза

- Платформа определяется через файл `1c-platforms.json` (поле `Exe`).
- Текущая платформа: **8.5.1.1343** (`C:\Program Files\1cv8\8.5.1.1343\bin\1cv8.exe`).
- Рабочая инфобаза: `Srvr="HOME";Ref="DocMng30"` (серверная, пользователь `Администратор`).

## Безопасность

- Секреты и пароли запрещено хранить в проекте (включая `build/`, логи и исходники).
- Пароль 1С хранится только в защищённом DPAPI-контейнере и читается на время запуска.
- `git push`, публикация и изменение удалённых репозиториев — только по явному разрешению.

## Структура проекта

- `src/` — рабочая область исходников (XML-выгрузки EPF/ERF, BSL-модули).
- `build/` — результаты сборки, тестирования и журналы (артефакты, логи, round-trip).
- `.opencode/` — проектная конфигурация AI-команды (агенты, config).
- `AGENTS.md` — этот файл (проектные правила).

## Роли AI-команды

- PRIMARY-агент (`build`) — оркестратор: координирует работу, сам код не правит (`edit: deny`).
- `1c-architect` — read-only исследование метаданных и технический план.
- `1c-developer` — единственный агент, которому разрешено изменять код, и только в `src/`.
- `1c-reviewer` — независимое read-only ревью реализации относительно плана.
- `1c-tester` — read-only верификация (BSL LS, сборка, smoke). Может запускать `1cv8.exe` через подтверждение.
- `1c-auditor` — финальный read-only контроль соответствия задаче, плану и правилам.

## Стандарты разработки и наборы скилов

Источники стандартов (порядок доверия):

1. Стандарты разработки 1С — https://v8std.ru/
2. 1C:Enterprise Developer Guide (8.3.27) — https://kb.1ci.com/1C_Enterprise_Platform/Guides/Developer_Guides/1C_Enterprise_8.3.27_Developer_Guide/?language=en
3. BSL Language Server — статическая диагностика кода.
4. Наборы скилов OpenCode (методологическая база, ниже).

Наборы скилов (не дублировать содержимое в prompt агентов — только ссылаться на них):

- `1c-core` — базовый цикл разработки 1С (исследование → реализация → BSL LS → сборка → smoke).
- `1c-metadata-probe` — исследование фактических метаданных до написания кода.
- `1c-managed-form` — preflight управляемых форм (реквизиты, команды, клиент/сервер).
- `1c-build-epf` — штатная сборка EPF/ERF через DESIGNER /LoadExternalDataProcessorOrReportFromFiles.
- `1c-testing` — уровни верификации (BSL LS → сборка → smoke → Vanessa/TestClient).

Соответствие агентов и скилов:

| Агент | Скилы |
|---|---|
| `1c-architect` | 1c-core, 1c-metadata-probe |
| `1c-developer` | 1c-core, 1c-managed-form, 1c-build-epf |
| `1c-reviewer` | 1c-core, 1c-managed-form, 1c-testing |
| `1c-tester` | 1c-build-epf, 1c-testing |
| `1c-auditor` | 1c-core, 1c-testing |

## Правила разработки

- `developer` не изменяет архитектурные правила — только реализацию по плану архитектора.
- Изменение `AGENTS.md`, `.opencode/`, `skills/` и конфигурации OpenCode выполняется только по отдельному разрешению пользователя.
- Перед изменением кода обязательно исследование метаданных (не выдумывать имена объектов).
- Перед завершением разработки обязательны: BSL-проверка, review и тестирование.
- `reviewer` и `tester` — независимые проверяющие, их вердикты обязательны.
- FAIL должен возвращаться `developer` на исправление.
- Количество автоматических итераций исправления ограничено **3**.
- При третьем FAIL — остановиться и передать проблему пользователю.
